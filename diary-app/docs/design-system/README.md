# 记得日记设计规范

版本：1.0 · 更新日期：2026-11-22 · 适用平台：iOS、Android、Web。

这套规范用于把已有素材和组件落实为一致、可恢复、易阅读的日记体验。覆盖视觉、组件状态、页面流程、交互、动效、素材加工与交付验收。设计和开发都以用户的记录内容为中心：写作及时响应，保存结果真实，回顾路径清楚，装饰不妨碍阅读。

## 使用规则

- “必须”是交付门槛；“建议”允许结合内容和设备调整，但需记录原因。
- 文中的“当前基础”来自代码结构核对，表示可以复用，不等于所有页面、所有平台均已验收。
- “新增目标”是后续实现要求。尺寸、时长、资源预算等项目数值是本产品的设计决策，外部标准依据在对应章节就近标注。
- 现有代码与规范冲突时，按差异单集中处理，不在单个页面临时增加另一套规则。涉及数据保存、权限和服务能力的文案必须服从真实结果。
- 所有尺寸默认为逻辑像素；字体用项目字号单位。导出图片的像素尺寸另行标注，不与设备 DPR 混用。

## 产品体验原则

1. **先写得下。** 不等待字体、插画、AI 或云同步完成才允许输入；错误时保留已有文字与附件选择。
2. **结果可相信。** 本机保存、云同步、导出与发送分别确认；动画结束、开关开启或计时器到点都不能代表成功。
3. **内容有层次。** 每屏一个主要任务；日记正文优先于装饰；日期、心情、人物与地点作为辅助信息。
4. **操作可恢复。** 可逆删除提供撤销或回收站入口；不可逆操作说明对象、范围和后果；中断后知道从哪里继续。
5. **主题可替换。** 不限定暖色风格；组件语义和交互不随主题改变；深浅色均单独验收。
6. **动效有用途。** 解释位置、状态和操作结果；跟随手势；允许取消；尊重系统减少动态效果偏好。

| 状态与可靠性 | 编辑草稿、本机保存、同步回执及错误分支已有实现 | 用本规范核对呈现与恢复入口；真实服务和跨设备流程单独验收 |

## 首轮实施范围

先以代码已有的“杂志 editorial”作为组件展示与验收的基准主题，保留其他外观选项。此选择用于建立可比较基线，不替换用户已有偏好；品牌最终图标仍由主题资源映射明确指定。

首轮完成三条核心路径：新建日记到保存与再次打开、搜索或日历到回顾详情、离线写作到联网同步或失败恢复。其他页面复用同一组件、状态和反馈规范。阶段交付及检查门槛见[验收与实施顺序](06-验收与实施顺序.md)。
