# 记得日记视觉与主题规范

本章定义所有主题共用的视觉结构。以现有 token 为基础，主题通过颜色、阅读字体、圆角和插画表达差异；信息层级、控件行为、触控区域和状态含义保持一致。

## 颜色语义

界面颜色必须取自 `useTheme().c`。图片中可有主题色，但业务控件不能从图片像素取色决定成功、危险或可用状态。

| 角色 | 现有 token | 用法 |
| --- | --- | --- |
| 页面与层次 | `bg`、`bgDeep`、`card`、`cardAlt`、`inputBg` | 页面底、分区底、卡片、次级表面、输入背景 |
| 文字 | `text`、`textSub`、`textMuted` | 正文、辅助、元信息；必要信息不能靠降低整体 opacity 弱化 |
| 主要动作 | `primary`、`textOnPrimary` | 主按钮和选中块；前景必须使用配对颜色 |
| 强调文字 | `primaryDark` | 文字链接、强调图标；不能直接用浅色 `primary` 替代 |
| 浅强调底 | `primarySoft`、`primaryFaint` | 选择项、轻量提示、标签背景 |
| 结构边界 | `divider`、`border` | 装饰分割、非必要卡片边界 |
| 必要边界与焦点 | `controlBorder`、`focusRing` | 识别输入、未选控件、键盘焦点；不能用装饰分割色替代 |
| 业务状态 | `danger/success/warning` 及对应 `Soft`、`info` | 删除/失败、已完成、需关注、说明；同时配文字或图形 |
| 禁用 | `disabledBg`、`disabledText` | 禁用状态；同时设置禁用语义和阻止操作 |
| 浮层 | `overlay`、`shadow` | 模态遮罩与投影；禁止整页透明造成正文透出 |

项目要求普通信息文字及占位说明达到 4.5:1；必要控件、选中标记和焦点线对相邻背景达到 3:1。项目信息文字统一按 4.5:1 验收，避免字号边界导致不同页面采用不同阈值。依据：[WCAG 文字对比度](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)、[非文字对比度](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html)。禁用文字保持可读是本项目的额外要求。

照片上叠加按钮时必须加独立稳定底色或遮罩，并针对亮图、暗图与高细节图测试。对比度应检查最终合成背景，不能只检查色板定义。错误、选中和心情不能只用颜色区分。

## 主题体系

当前代码有 7 个 `StyleKey`：杂志 `editorial`、温润 `warm`、清冷 `cool`、墨白 `ink`、森野 `forest`、樱雾 `sakura`、旧纸 `kraft`；另有 10 个可选强调色。实现以 `palette.ts` 为准。旧验收资料中的六主题范围不能自动覆盖新增的杂志主题。

主题与 10 套生成素材是两套维度：主题控制组件，素材包提供插画和图像资源。每种风格绑定一套插画包（`ILLUSTRATION_PACKS`），引导页、封面、空状态、成功反馈、隐私锁与云同步插画全部随风格切换；线绘陪伴、墨白、旧纸三套墨色/灰洗笔触在深色下使用有意的浅色底托（`darkPlate`），其余风格直接使用透明插画。

| 产品风格 | 素材包 | 状态 | 深色底托 |
| --- | --- | --- | --- |
| 线绘陪伴 | `04-ink-companion` | 已接入 | 是 |
| 杂志 | `09-editorial-photo` | 已接入 | 否 |
| 温润 | `08-scrapbook` | 已接入 | 否 |
| 清冷 | `02-azure` | 已接入 | 否 |
| 墨白 | `01-monochrome` | 已接入 | 是 |
| 森野 | `03-mint` | 已接入 | 否 |
| 樱雾 | `05-lilac` | 已接入 | 否 |
| 旧纸 | `06-ink-mountains` | 已接入 | 是 |
| 彩色时刻 | `07-geometric` | 已接入 | 否 |
| 深蓝星笺 | `10-midnight` | 已接入 | 否 |

插画包位槽为 `onboardWrite` / `onboardMemory` / `cover` / `emptyBook` / `emptySearch` / `savedSuccess` / `privacyLock` / `cloudSync` / `memorySticker`，由 `useIllustrations()` 按当前风格解析，未配置时回退线绘陪伴。陪伴小鸟（`companionBird`）是线绘陪伴的角色资产，其他风格不显示。通用心情、天气和功能插画应按页面角色使用，避免同一层级同时出现多种立体、线绘、拼贴风格。

主题切换必须保留日记、当前草稿、导航位置、字号与其他未被明确修改的偏好。用户手动切换风格时可采用该风格默认强调色；之后单独选强调色不得重置风格。

## 排版与字体

所有字体通过 `ThemeProvider` 和文本包装组件选择。界面字体与阅读字体分工如下：

| 角色 | 基准字号与行高 | 字体与应用 |
| --- | --- | --- |
| 品牌大标题 `display` | 30 / 42 | 阅读字体，用于首页或引导的大标题 |
| 编辑式页标题 `h1` | 22 / 32 | 阅读字体；大标题式页面使用，避免用于密集表单 |
| 分区标题 `h2` | 18 / 27 | 阅读字体；用于内容分组 |
| 控件标题 `h3` | 16 / 24 | 系统 UI 字体，导航和紧凑控件优先使用 |
| UI 正文 `body` | 15 / 24 | 系统 UI 字体 |
| 日记标题 `readingTitle` | 22 / 34 | 用户选择的阅读字体 |
| 日记正文 `bodySerif` | 16 / 字号 × 行距 | 用户选择的宋体、黑体、楷体；别名不代表仅宋体 |
| 辅助 `sub` | 13 / 21 | 系统 UI 字体 |
| 说明 `caption`、`tiny` | 12 / 19、12 / 18 | 系统 UI 字体；不承担唯一的重要操作说明 |

这张表与当前 `ThemeProvider.tsx` 对齐：`display/h1/h2` 是阅读字体的品牌例外。标准居中导航、按钮、输入框、时间、统计数字和错误文字采用 UI 字体。不要依据旧验收文字把全部标题一概当作系统字体。

字号档位沿用 `standard=1`、`large=1.1`、`xlarge=1.22`；阅读行距沿用 `1.55 / 1.8 / 2.05`。字号经 `fs()` 计算，不再在页面重复乘系数。平台系统放大与应用档位叠加时也必须可用；不能通过关闭系统字体缩放来解决溢出。

原生自定义字体的半粗字重使用真实 `readingBold` 字族，避免合成字重丢失。字体未就绪或加载失败时使用系统回退，不阻塞写作。UI 文本不随用户阅读字族变化。长按钮文案允许增高或折行；重要错误说明不省略。列表摘要可以截断，详情正文完整呈现。

## 间距与布局

| 基础项 | 约定 |
| --- | --- |
| 现有间距 | `space.xs/sm/md/lg/xl/xxl = 4/8/12/16/20/28` |
| 使用原则 | 图标与文字 8；相关字段 12；卡片内边距 16；手机页面横向留白 20；主要分区 28 |
| 小屏降级 | 宽度小于 360 时页面横向留白可降为 16，不缩小触控区 |
| 扩展间距 | 24、32、40、48 等用于大图与页面留白；需集中加入 token，避免逐页新增常数 |
| 阅读容器新增目标 | 平板与桌面正文建议最大宽 720，居中；当前 `contentWidth` 仍保留用户偏好，统一解析宽度后再接入 |
| 浮层当前基线 | 底部面板最大宽 520，最大高约可用屏幕的 86%；超长内容在内部滚动 |
| 安全区域 | 顶栏、底栏、主按钮避开系统栏和手势区；内容底部补足固定栏遮挡空间 |

320 宽、短屏、横屏和键盘打开时必须仍能访问主要操作；没有空间时改为纵向排布或内部滚动。宽屏不直接把手机按钮与正文拉满整屏。网页 200% 缩放下仍可完成主要流程。

## 圆角与层次

基础圆角为 `6 / 10 / 14 / 18 / 24 / 999`，分别来自 `radius.xs…pill`。运行时经 `r()` 按风格缩放：杂志 0.65、温润 0.8、清冷 0.5、墨白 0.25、森野 0.7、樱雾 1.15、旧纸 0.35；胶囊及微小圆角按 `scaleRadius()` 的规则处理。

清冷、墨白和旧纸用边框表达层级，不添加卡片阴影；其余主题复用 `theme.frame` 的轻投影。深色模式优先通过表面层次和边框区分，不加更重阴影。浮层遮罩只服务当前顶层模态，不能叠出越来越黑的背景。

## 图标与插画

- UI 图标基准槽为 24；普通控件可用 20–22；同一组线宽统一。项目现有 Lucide 控件线宽约 1.6–1.8，首轮以 1.8 为目标归一，紧凑尺寸按光学校正。
- 图标视觉大小与触控区分开：项目交互目标至少 44×44，不能因为图形只有 20 而缩小点击范围；重叠热区必须拆开。
- 工具栏与导航优先使用 Lucide 或原创 SVG。生成的 PNG 图标用于风格参考、较大展示或经小尺寸验证的特定皮肤；不自动认定为合格的 24 像素图标。
- 图标颜色取主题前景色；选中状态除颜色外配指示条、勾选或形状。纯图标按钮必须有可访问名称。
- 生成插画用 `contain` 保留完整轮廓；摄影封面可用 `cover`，逐张登记焦点。禁止统一圆形裁切导致书本、角色或锁等主体被截断。
- 空状态插画建议 120–180，短屏时可缩小或隐藏；标题、说明和行动按钮保留。引导插画与文案分层，文案保持真实文字。

## 深色模式

深色模式必须独立检查控件、图片、遮罩、媒体和系统界面。线绘 PNG 不使用全图反相；可换 SVG 主题色、选择深色资源，或为插画设置符合主题的独立底板。底板是有意的卡片结构，不能出现来源不明的白色矩形边缘。

信纸和摄影属于用户内容背景时，明确约定正文颜色与稳定遮罩；不能跟随系统主题后让原本的黑字落在深色图上。主题切换无需额外庆祝动画，也不得让受保护内容短暂显露。

## 视觉交付检查

- 同屏主要按钮层级清晰，颜色均来自语义 token。
- 320、390、760、1280 宽及浅深模式的长标题、长标签和最大字档均可阅读。
- UI 字体和阅读字体分工正确，字体失败可继续输入。
- 对比度按实际页面组合计算；图片、透明度与选中浅底纳入检查。
- 同一流程的插画语言统一，工具栏图标在实际显示尺寸清楚可辨。
