## 2026-11-21 补充：人机验证门与认证修复

用户反馈注册邮箱验证码慢、发码接口无人机验证/限流。经实测 CloudBase 发码接口正常（平台代发延迟属其固有特性），并修复了两个真实缺陷。

### 修复的缺陷

- **注册密码不生效**：新版 SDK 的 `updateUser` 明确拒绝改密，旧的"注册后补设密码"静默失败，验证码注册用户永远无法密码登录。改为 SDK `signUp({email|phone, password})` 流程——同一条验证码完成注册并把密码写入账号；已注册账号则等价验证码登录。发码后再改密码需重新获取验证码（界面已拦截提示）。
- **找回密码不可用**：验证后同样调用被拒的 `updateUser`，密码永远改不了；且界面谎称"点击邮件链接"。改为 `resetPasswordForEmail`（手机/邮箱统一）：验证码 + 新密码直接写入并自动登录。

### 人机验证与限流

- 自建图形验证码：服务端下发含噪点/干扰线/不可见诱饵字符的 SVG 图形码（无 0/O/1/I 易混字符），答对换一次性 ticket（HMAC 签名、绑定客户端、180 秒、单次核销）。
- 发码硬门：`POST /cb/auth/v1/verification` 改由 jide-feedback 服务代理，无有效 ticket 直接 401，核销后才转发 CloudBase；CloudBase 自带滑块 token（`captcha_token`）视为等效证明放行。
- 限流三层：nginx `limit_req`（发码 30r/m、验证接口 30r/m、登录注册等 10r/m，统一 429 JSON）；服务端每 IP 每小时 20 次图形码、每账号每日 5 次发码、每 IP 每日 20 次、全局每日 500 次；图形码每题 5 次尝试。
- 三个发码入口（注册/验证码登录/找回密码）在 Web 端先弹图形验证；RN 端直连 CloudBase 网关不经过此门（也不受 HTTP 明文影响范围之外的保护）。
