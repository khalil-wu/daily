# UI 统一与优化规范

## 目标

记得日记的界面应保持白色、暖灰、人文、克制的移动端应用气质。整体方向不是冷色科技风，也不是装饰型落地页，而是面向普通日记用户的低压力记录工具：打开后能快速写、轻松回看、明确知道每个按钮会做什么。

本规范基于当前 Expo / React Native Web 项目和 `ui-ux-pro-max` 的移动端检查规则整理，用于后续所有 UI 修改和评审。

## 全局设计原则

- 背景以白色和暖灰为主，避免大面积蓝紫、冷灰、重渐变。
- 社区页保持 X/Twitter 式扁平信息流，正文不使用大卡片包裹。
- 写日记页优先服务输入体验，工具项通过弹层渐进展示。
- 页面只保留一个最明确的主操作，其他操作降级为图标按钮、次级按钮或设置行。
- 不使用 emoji 作为结构性图标，继续使用 `lucide-react-native`。
- 不在用户界面里出现 README、Markdown 等开发者概念，面向普通用户使用“排版”“效果”“清单”等语言。

## 触控与交互标准

- 所有可点区域最小触控尺寸为 `44x44`。
- 相邻触控目标之间至少保留 `8` 间距。
- 图标按钮必须有 `accessibilityRole="button"` 和明确的 `accessibilityLabel`。
- `Pressable` 必须满足二选一：有真实 `onPress`，或明确 `disabled`。
- 只读信息不要做成按钮样式；看起来能点的元素必须能触发状态变化、跳转或弹层。
- 禁用状态需要同时有语义 `disabled` 和视觉降权。
- Press 状态只改变背景、透明度、颜色或轻微 scale，不允许导致布局跳动。
- 模态和底部弹层必须支持点击遮罩关闭，并有可见关闭按钮。

## 动效标准

- 微交互动效控制在 `150-300ms`。
- 进入动画可以使用 opacity + translateY；退出动画应更快。
- 避免动画 width、height、top、left 等会触发布局重排的属性。
- 已有 `useReducedMotion` 的位置要继续遵守系统减少动态效果设置。
- 动画必须表达状态变化，例如弹层出现、保存反馈、列表项进入，不做无意义装饰。

## 字体与排版

- UI 字体统一使用 `typography.fontFamily.display` / `sans`，保持 Claude-like 的克制、人文、清晰。
- 长文输入和阅读可以使用 `typography.fontFamily.reading`，但按钮、导航、标签、设置行、社区 feed 统一使用 UI 字体。
- 正文最小建议 `16`，辅助文字不低于 `11`，重要按钮文字不低于 `13`。
- 正文行高保持舒适，不压缩字距，不使用负 letter spacing。
- 社区正文保持紧凑，不使用超大标题；日记详情和写作区可以更有阅读感。

## 颜色与层级

- 所有页面优先使用 `src/theme/tokens.ts` 中的语义 token。
- 不在页面组件里随意新增硬编码色值；确实需要新增颜色时先补 token。
- 主要文本使用 `colors.textPrimary`，辅助文本使用 `colors.textSecondary` 或 `colors.textTertiary`。
- 分割线使用 `colors.divider` 或 `colors.line`，社区 feed 优先用 hairline divider 建立层级。
- 模态遮罩统一使用 `colors.scrim` 或 `alpha.scrim`。
- 当前方向偏扁平，阴影只保留给底部弹层、模态和必要浮层。

## 页面优化方向

### 首页

- 星图是首页第一视觉重点，节点点击必须有稳定反馈。
- 关系线、箭头、关系文字保持轻量，不能抢过人物头像。
- 指标卡如果可点击，需要在文案和 pressed 状态上表现出来。
- “私密”指标当前是信息展示，不应做成可点击样式，除非后续跳转私密设置。

### 写日记 / 编辑日记

- 顶部只保留“取消”和“发表/保存”的明确动作。
- 正文输入区优先，照片、位置、录音、人物、心情、排版作为设置行进入弹层。
- 照片入口放在发布设置区域，点击后弹出“选择照片 / 现场拍摄”。
- 录音入口应显示开始、停止、已添加数量，并说明语音会跟日记一起保存。
- 排版工具用普通用户语言：标题、重点、引用、清单、待办、分隔。
- 心情不固定常驻底部，使用弹层选择后关闭。

### 时间线

- 筛选按钮需要清晰 selected 状态。
- 年份筛选、照片筛选、私密筛选的视觉级别要一致。
- 记忆卡片点击进入详情，卡片内部如果以后增加更多按钮，需要防止事件冒泡误触详情。

### 人物

- 人物列表项点击进入人物详情。
- 新增人物按钮保持显眼，但不要比页面内容更重。
- 人物关系选择使用按钮/标签样式，selected 状态明确。

### 社区

- 社区为扁平 feed：头像左侧、内容右侧、底部操作行。
- 关注、转发、评论、喜欢必须真实可点。
- 评论当前跳转日记详情，后续补评论详情页后再改为打开评论流。
- 关注 Tab 后续应基于关注状态过滤内容，现在不能伪装成完整关注流。
- 通知按钮可以先显示空状态弹层，但不能无反应。

### 搜索

- 输入框自动聚焦，清除按钮只在有内容时出现。
- 搜索结果点击进入人物或后续扩展到日记详情。
- 空状态需要说明当前没有匹配内容。

### 我的 / 设置

- 设置项保持系统列表风格，不使用营销卡片。
- 应用锁开关、PIN 输入、私密设置、备份恢复需要明显错误提示和恢复路径。
- 危险操作保持确认弹窗，且危险按钮与普通按钮视觉区分。

## 组件统一要求

- `PrimaryButton`：统一承载主操作，支持 disabled、pressed feedback、加载文案。
- 图标按钮：最小 `40x40` 视觉尺寸，配合 `hitSlop` 满足触控。
- 设置行：左图标、中间 label/value、右侧 chevron；点击后进入弹层或子页面。
- 底部弹层：统一标题、关闭按钮、遮罩、最大宽度、圆角和进入动画。
- Feed item：使用 divider，不使用厚阴影；操作行图标尺寸和 strokeWidth 统一。
- 空状态：短标题 + 一句解释 + 可选操作，不写长说明。

## 验收清单

- 所有可点击元素有真实事件或 disabled。
- 所有图标按钮有无障碍标签。
- 移动端 375px 宽度无横向滚动。
- 主流程按钮触控目标不小于 `44x44`。
- 弹层可通过关闭按钮、遮罩和系统返回关闭。
- 减少动态效果开启后不出现强动画。
- 社区 feed 没有大卡片正文框。
- 写日记页底部不再常驻照片、拍摄、人物、心情工具栏。
